# Quelle remediation — chase & double-check every source (master plan)

**Status:** Draft for user review · **rev:** 2026-05-21 (2nd revision)
**Author:** Claude (Opus 4.7)
**Replaces:** the previous Q1–Q5 outline of this file (kept as historic reference in `_neo4j/QUELLE_REMEDIATION/legacy_q1_q5_outline.md`).

> **What changed in this revision.** The previous plan extracted URLs and surfaced them but did not verify them. This revision **chases each URL** (does it actually load?) and **double-checks each citation** (does the URL's content actually contain the cited excerpt?). Six agents do the work. The orchestrator (me) coordinates. Every fact in the graph ends up with a verifiable provenance trail — or an explicit `:DataIssue` saying why it couldn't be verified.

---

## §1 The mission, in one paragraph

For every piece of information in `mit-bestand`, the user must be able to answer **four questions** in two clicks or fewer:

1. **What URL is this from?** (the cited source)
2. **Is that URL still alive?** (reachability)
3. **Does that URL actually say what we claim?** (content match)
4. **If the answer to 2 or 3 is "no", what level of trust does this fact carry?** (so the user sees the gap honestly)

The previous plan answered only question 1. This plan answers all four.

## §2 What's broken right now (cold context)

If you're an agent arriving at this plan for the first time, read this once. The current state, end of 2026-05-21:

- 4,151 nodes / 25,377 relationships in `mit-bestand` (post-review-based-remediation Stage 4 audit).
- `:Quelle` (~1,570 nodes) holds five subtypes via a `.quelltyp` property; no first-class labels.
- ~95 of 100 `case_markdown :Quelle` nodes carry full markdown dossier text in `Quelle.text_content` — bloat, mistake from R7.d.
- ~3,074 edges marked `evidence_origin='source_curated'`. 259 of them have no `evidence_excerpt`.
- ~1,470 `:ZITIERT_QUELLE` edges (citation chain), but no agent has ever checked whether the cited URL was reachable, let alone whether it contained the claimed excerpt.
- The `evidence_excerpt` text on `:BELEGT_IN` edges is sometimes verbatim from a source, sometimes generated by a migration (Repair D, etc.), sometimes paraphrased by a research agent. The graph doesn't currently distinguish.

The graph is internally consistent but **externally unverified**.

## §3 Target schema (introduced by S1–S5)

### §3.1 On `:ExternalLink` (the URL-bearing node)

```
:Quelle :ExternalLink {
  // Identity
  id, url, title,                           // already there OR added by S1

  // Discovery provenance (S1)
  url_origin,                               // 'dossier_md_link' | 'dossier_bare_url'
                                            // | 'pre_existing_quelle' | 'edge_property' | 'node_property'
  first_seen_in_dossier,                    // dossier id
  also_in_dossier,                          // list<dossier_id>

  // Reachability (S2)
  url_status,                               // 'reachable_2xx' | 'reachable_3xx' | 'dead_4xx' | 'dead_5xx'
                                            // | 'timeout' | 'dns_failure' | 'tls_failure'
                                            // | 'unsupported_scheme' | 'unchecked'
  url_last_checked_at,                      // date
  url_http_code,                            // int
  url_final_url,                            // string (after redirects)
  url_redirect_chain,                       // list<string>
  url_content_type,                         // 'text/html' | 'application/pdf' | …
  url_content_length_bytes,                 // int
  url_last_modified_header,                 // string
  url_probe_attempts,                       // int (for retries)

  // Wayback fallback (S2)
  url_wayback_snapshot,                     // string (archive.org URL) if Wayback could replace a dead URL
  url_wayback_timestamp,                    // string

  // Cached body location (S2; for S3 to consume)
  url_body_cache_path                       // relative path to logs/url_bodies/<hash>.{html|pdf}
}
```

### §3.2 On every citation edge (`:ZITIERT_QUELLE`, `:BELEGT_IN`)

```
:ZITIERT_QUELLE {
  // Already there or added by S1
  locator,                                  // 'S1' | 'S7' | 'P1' | 'bare'
  evidence_excerpt,                         // claim text from the dossier
  evidence_source_id,                       // dossier id

  // Content verification (S3)
  verification_status,                      // 'verbatim_match' | 'paraphrase_match' | 'no_text_match'
                                            // | 'target_page_dead' | 'unsupported_content_type'
                                            // | 'fetch_error' | 'skipped_no_excerpt'
                                            // | 'unchecked'
  verification_score,                       // float 0.0–1.0
  verification_method,                      // 'exact' | 'fuzzy_85' | 'token_80' | 'none' | 'skipped'
  verified_at,                              // date
  verification_attempts,                    // int
  verification_notes                        // string (free-text reason for no_text_match)
}
```

`:BELEGT_IN` edges that point at a `:Dossier` rather than an `:ExternalLink` inherit the same verification model when traced through to a URL (one extra hop).

### §3.3 On `:Projekt`, `:Bauwerk`, `:Akteur` (denormalised for visibility — S5)

```
{
  source_urls,                              // list<string>  (already added by Q4 in legacy plan)
  source_count,                             // int

  // NEW from S5
  source_quality_summary,                   // map {n_verbatim, n_paraphrase, n_no_match,
                                            //      n_dead, n_unchecked}
  source_freshness_summary,                 // map {n_reachable, n_dead, n_unchecked,
                                            //      latest_check_date}
  source_trust_score,                       // float 0.0–1.0 — single-number summary
                                            // for sorting in Browser
  source_urls_updated_at
}
```

## §6 What this plan deliberately does NOT do

- **Doesn't generate excerpts.** If `evidence_excerpt` is missing on a `source_curated` edge, S3 marks the citation `skipped_no_excerpt` and S6 emits `:DataIssue {kind:'citation_no_excerpt_to_verify'}`. We do not synthesize evidence to make a verification pass.
- **Doesn't paraphrase-fix.** If a content match needs full semantic understanding (e.g., the page rephrases the claim in entirely different words), S3 marks it `no_text_match` and the user can re-curate manually.
- **Doesn't try to repair dead URLs by web-searching.** Wayback Machine fallback only.
- **Doesn't run a headless browser.** JS-rendered pages without a static body get tagged `unsupported_javascript_required`.
- **Doesn't translate.** German source pages cited with German excerpts; English with English. Cross-language matches return `no_text_match`.

                       {n_verbatim: 4, n_paraphrase: 2, n_no_match: 1, n_dead: 0, n_unchecked: 0}

The user **immediately** sees: 7 sources, all alive, 6 of 7 content-verified, trust score 0.86. No clicking through properties. No multi-hop query.

## §8 Schema invariants (cross-cutting)

After S1–S6 complete, the following MUST hold (audited by S6):

| ID | Invariant |
|---|---|
| QV1 | Every `:Quelle` is also `:Dossier` OR `:ExternalLink` OR `:ResearchDocument` OR `:SectionRef` OR `:OntologyAnchor`. |
| QV2 | Every `:ExternalLink` has non-null `.url`. |
| QV3 | Every `:ExternalLink` has non-null `.url_status` (not `'unchecked'`). |
| QV4 | Every `:ZITIERT_QUELLE` edge has non-null `.verification_status` (not `'unchecked'`). |
| QV5 | No `:Dossier` carries `text_content` (it was stripped by S4). |
| QV6 | Every `:Projekt`, `:Bauwerk`, `:Akteur` has `source_urls` (may be empty list). |
| QV7 | Every `:Projekt`, `:Bauwerk`, `:Akteur` has `source_quality_summary` (may have all-zero counts). |
| QV8 | For every `evidence_origin='source_curated'` edge, there exists a verification status (≠`unchecked`). |
| QV9 | No `:ExternalLink.url` contains UTM params or trailing slashes (normalised by S1). |
| QV10 | Every `:DataIssue` raised by S2/S3/S6 has a `:CONCERNS` edge to its subject node. |

If any invariant fails, S6's audit returns FAIL and the user is alerted.

## §10 Decisions you should make before any agent runs

These block specific phases. Defaults are recommended; redline if you disagree.

| ID | Question | Default | Blocks |
|---|---|---|---|
| QD-1 | Should S2 archive every reachable URL to Wayback Machine proactively? | **YES** — submit a `web.archive.org/save/<url>` request for every reachable URL. Rate-limit to 3 req/min/host. Cheap insurance. | S2 |
| QD-2 | Should S2 respect `robots.txt`? | **YES** — for any URL whose robots.txt disallows fetching, mark `url_status='blocked_by_robots'` and skip body cache. | S2 |
| QD-3 | What's the fuzzy-match threshold for S3 Tier B (paraphrase)? | **85** (RapidFuzz `partial_ratio`). Lower → more false positives; higher → more false negatives. | S3 |
| QD-4 | What's the token-overlap threshold for S3 Tier C? | **0.80** of significant tokens. Significant = non-stopword, length ≥ 3. | S3 |
| QD-5 | Should S3 also try the Wayback snapshot if the live URL is dead but a snapshot exists? | **YES** — Wayback is treated as a valid fallback source, but verification on the snapshot is tagged `verification_method='wayback'`. | S3 |
| QD-6 | What does S3 do when `evidence_excerpt` is in German and the page is in English (or vice versa)? | **Mark `verification_status='no_text_match'`** with note `language_mismatch`. Cross-lingual matching is out of scope. | S3 |
| QD-7 | Should S5 compute `source_trust_score`? | **YES** — single-number summary makes Browser sortable. Formula: weighted average over per-edge verification scores, with `url_status` as a multiplier. See [AGENT_S5_visibility.md §5](QUELLE_REMEDIATION/AGENT_S5_visibility.md) for the formula. | S5 |
| QD-8 | What HTTP user-agent should S2 send? | `mit-bestand-source-prober/1.0 (research-graph; contact: <Kinan email>)` — be honest, identify the agent, supply a contact. | S2 |
| QD-9 | Should S6 add a CI gate that fails ingestion if any `:Dossier.text_content` is non-null post-import? | **YES** — pre-flight script at `_scripts/validate_no_text_content.py`. | S6 |
| QD-10 | What's the timeout for an HTTP probe? | **10 s connect + 20 s read.** Slow but reliable for government / university sites. | S2 |
| QD-11 | What's the maximum body size to cache? | **5 MB.** Larger → tag `url_body_too_large` and skip caching. | S2 |
| QD-12 | When S3 detects a page returning a "consent / cookie wall" before content, does it count as `no_text_match`? | **YES** + note `cookie_wall_detected`. Future work could parse around the wall. | S3 |

## §11 Risks and mitigations

| Risk | Mitigation |
|---|---|
| S2 hammers external hosts → blocking, IP bans | Rate-limit max 1 req/sec/host, max 30 req/min total. Identify in User-Agent. Respect 429. |
| S2 caches grow huge (1,000 URLs × 1 MB avg = 1 GB) | Cap body cache at 5 MB per URL. Gzip-compress in cache. Total budget: 2 GB. |
| S3's fuzzy matching produces false positives ("paraphrase" when it's just coincidental token overlap) | Three tiers with explicit thresholds. Each result records its method + score. User can re-tune. |
| Some pages are pdf / javascript-only | Tag explicitly; don't fail the run. Treat as `unsupported_*`. |
| Wayback Machine may not have a snapshot of the URL we want | Tag `url_wayback_unavailable`. Don't block. |
| The 5 dossiers without text_content (FU-8) can't have URLs extracted by S1 | S4 attempts to resolve the path. If still unresolvable, emit `:DataIssue {kind:'dossier_path_unresolvable'}`. |
| Running S2+S3 against the live db while users query is happening | All writes are tagged with `migration_origin`; idempotent; can run during low-traffic windows. |
| The verification round produces an avalanche of `:DataIssue` nodes (potentially 1,000+) | This is the goal — the issues already exist, we're surfacing them. S6 produces an exec summary. |
| Cross-language excerpt vs. page (German excerpt, English page) | Per QD-6, tag `no_text_match` with note `language_mismatch`. Future improvement: parallel translation. |
| Some excerpts are auto-generated (Repair D) → won't match any source page | These edges are `evidence_origin='topology_synthesized'` after R1. S3 SKIPS them (no verification needed; they're acknowledged synthetic). Only `source_curated` edges get verified. |

## §12 Glossary (one screen)

- **`:Quelle`** — umbrella label for any source-bearing node. Surface kept for back-compat.
- **`:Dossier`** — secondary label on `:Quelle` for our internal `.md` files (was `quelltyp='case_markdown'`).
- **`:ExternalLink`** — secondary label on `:Quelle` for actual URLs cited by dossiers/research/registry.
- **`:ResearchDocument`** — secondary label for internal research markdown anchors.
- **`:SectionRef`** — secondary label for S-ref sub-nodes (`q_<slug>_s1`, etc.).
- **`url_status`** — from S2. Reachability outcome.
- **`verification_status`** — from S3. Did the URL's content match the cited excerpt?
- **`source_quality_summary`** — from S5. Per-Projekt/Bauwerk/Akteur breakdown of verification outcomes.
- **`source_trust_score`** — from S5. Single number 0.0–1.0.
- **`:DataIssue`** — pre-existing label from R8. New `kind` values added by S2/S3/S6.

## §13 What success looks like

After S1–S6 complete and S6 audit passes:

1. `MATCH (p:Projekt {id:'p_stuttgart_210'}) RETURN p` in Browser shows `source_urls`, `source_quality_summary`, `source_freshness_summary`, `source_trust_score` immediately on the property panel.
2. `MATCH (e:ExternalLink) WHERE e.url_status = 'unchecked' RETURN count(e)` returns 0.
3. `MATCH ()-[z:ZITIERT_QUELLE]->() WHERE z.verification_status = 'unchecked' RETURN count(z)` returns 0.
4. `MATCH (d:Dossier) WHERE d.text_content IS NOT NULL RETURN count(d)` returns 0.
5. `MATCH (i:DataIssue) WHERE i.found_by STARTS WITH 's2_' OR i.found_by STARTS WITH 's3_' RETURN i.kind, count(i)` returns a breakdown — the user knows exactly which sources failed verification.
6. The CLI tool `python _scripts/find_sources.py <node_id> --verify` works on any node, prints a per-URL verification status, opens any URL in the browser on `--open`.
7. `_neo4j/FINAL_QUELLE_AUDIT.md` exists at repo root with the full breakdown.
8. The new pre-flight script `_scripts/validate_no_text_content.py` is added to `_neo4j/intake/README.md` as a required check for every future ingestion.
