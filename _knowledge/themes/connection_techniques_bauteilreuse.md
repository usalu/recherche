## Graph recommendations

`vt_reversible_fuegung` should be modeled as a **parent / superclass**, not as a peer that competes with concrete techniques. Add child edges from `vt_verschraubung`, `vt_klemmverbindung`, `vt_steckverbindung`, and any future `vt_holzduebel` only when the specific implementation is dry, accessible, and demountable.

Keep **reversibility as a case-level property**, not only as a node property. The Recyclinghaus example shows why: it uses a screw-like connection, but the beech screws are reported as becoming inseparable, so `vt_verschraubung` is not automatically reversible.

For missing nodes, the evidence above supports adding:

- `vt_bolzenverbindung`
- `vt_demontierbarer_schwerlastanker`
- `vt_stahlverbinder_holz`
- façade/module nodes such as `vt_stahlrahmen_fassadenmodul`

I would **not** add `vt_holzduebel` or `vt_nagelung` from these project examples unless separate source evidence is added; the current project evidence did not show a true wood-dowel case or a nailed reuse case.
